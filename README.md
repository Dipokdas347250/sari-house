# শাড়িঘর

বাংলা ভাষার একটি সম্পূর্ণ ই-কমার্স দোকান — শাড়ি ও দেশীয় পোশাকের জন্য। ক্রেতার দিকে
পণ্য ব্রাউজিং, কার্ট, উইশলিস্ট, কুপন, ক্যাশ-অন-ডেলিভারি ও মোবাইল ব্যাংকিং চেকআউট এবং
অর্ডার ট্র্যাকিং; দোকানির দিকে একটি পূর্ণ অ্যাডমিন প্যানেল।

সমস্ত লেখা, সংখ্যা ও তারিখ বাংলায় — দাম `৳ ৬,২০০`, তারিখ `২২ সেপ্টেম্বর ২০২৬`।

---

## প্রযুক্তি

| স্তর | যা ব্যবহার হয়েছে |
| --- | --- |
| ফ্রেমওয়ার্ক | Next.js 16 (App Router, Turbopack, React Compiler) |
| ভাষা | TypeScript, React 19 |
| স্টাইল | Tailwind CSS 4 |
| ডাটাবেস | SQLite + Prisma ORM 7 (`better-sqlite3` ড্রাইভার অ্যাডাপ্টার) |
| অথ | নিজের JWT সেশন (`jose`) + `bcryptjs`, কুকিতে রাখা |
| অন্যান্য | zustand (কার্ট/উইশলিস্ট), zod (ভ্যালিডেশন), sonner (টোস্ট), framer-motion, swr |

ডাটা যাচাই দুই জায়গায় হয় — ফর্মে এবং সার্ভার অ্যাকশনে (`zod`)। অ্যাডমিন এলাকার
প্রতিটি সার্ভার অ্যাকশন আলাদা করে `requireAdmin()` দিয়ে পাহারা দেওয়া, শুধু
মিডলওয়্যারের উপর ভরসা করা হয়নি।

## শুরু করা

```bash
npm install                 # postinstall স্বয়ংক্রিয়ভাবে prisma generate চালায়
cp .env.example .env        # তারপর AUTH_SECRET বদলে নিন
npm run db:migrate          # টেবিল তৈরি
npm run db:seed             # নমুনা ক্যাটাগরি, পণ্য, রিভিউ, অর্ডার ও অ্যাডমিন
npm run dev
```

দোকান → <http://localhost:3000> · অ্যাডমিন → <http://localhost:3000/admin>

`db:seed` শেষে অ্যাডমিনের ইমেইল ও পাসওয়ার্ড টার্মিনালে ছাপা হয় (ডিফল্ট
`admin@sharighor.com` / `admin123`, `.env` থেকে বদলানো যায়)।

### এনভায়রনমেন্ট ভেরিয়েবল

| নাম | কাজ |
| --- | --- |
| `DATABASE_URL` | SQLite ফাইলের ঠিকানা, যেমন `file:./dev.db` |
| `AUTH_SECRET` | সেশন টোকেন সই করার চাবি — অন্তত ১৬ অক্ষর, **লাইভে অবশ্যই বদলান** |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | seed চালানোর সময় প্রথম অ্যাডমিন অ্যাকাউন্ট |
| `NEXT_PUBLIC_SITE_URL` | সাইটম্যাপ, robots ও schema.org ডেটায় ব্যবহৃত পূর্ণ ঠিকানা |

## যেভাবে কাজ করে

**অর্ডার।** চেকআউটে দাম সার্ভারেই আবার হিসাব হয় — দাম, কুপন ও ডেলিভারি চার্জ
ব্রাউজার থেকে পাঠানো সংখ্যার উপর নির্ভর করে না। এক ট্রানজ্যাকশনে অর্ডার তৈরি, স্টক
কমানো, `soldCount` বাড়ানো ও কুপনের ব্যবহার গোনা হয়। অর্ডার নম্বর `SG-260922-4821`
ধরনের, আর ক্রেতা ফোন নম্বর + অর্ডার নম্বর দিয়ে `/track` থেকে অবস্থা দেখতে পারেন।

**ডেলিভারি চার্জ।** ঢাকার ভেতরে/বাইরে আলাদা, একটি নির্দিষ্ট টাকার উপরে ফ্রি — তিনটি
মানই অ্যাডমিন সেটিংস থেকে বদলানো যায় (`calcDelivery()`).

**পেমেন্ট।** ক্যাশ অন ডেলিভারি, বিকাশ ও নগদ। বিকাশ/নগদে ক্রেতা সেন্ডার নম্বর ও
ট্রানজ্যাকশন আইডি দেন; দোকানি অ্যাডমিন প্যানেলে মিলিয়ে দেখে `paid` করে দেন।

**স্টক।** অর্ডার বাতিল করলে স্টক ও `soldCount` আগের অবস্থায় ফিরে যায়, আর বাতিল অর্ডার
আবার চালু করলে আবার কেটে নেওয়া হয় (`updateOrderStatus`)। অর্ডার `delivered` হলে
ক্যাশ অন ডেলিভারির টাকাও পরিশোধিত ধরা হয়।

**রিভিউ।** ক্রেতার দেওয়া রিভিউ প্রথমে `isApproved: false` থাকে; অ্যাডমিন অনুমোদন
করলেই পণ্যের পাতায় ও রেটিং হিসাবে যোগ হয়।

**পণ্য কতবার দেখা হলো।** পাতা খোলার পর ব্রাউজার থেকে গোনা হয় (`ViewTracker`), তাই
ক্রলার বা প্রিফেচ হিসাবে ঢোকে না; এক সেশনে একটি পণ্য একবারই গোনা হয়। সংখ্যাটি
অ্যাডমিনের পণ্য তালিকায় দেখা যায়।

**সেটিংস।** দোকানের নাম, ফোন, ঠিকানা, সোশ্যাল লিংক, বিকাশ/নগদ নম্বর, ডেলিভারি চার্জ
ও ঘোষণা বার — সব `Setting` টেবিলে key-value হিসেবে। ডিফল্ট মান
`src/lib/constants.ts` এ (`DEFAULT_SETTINGS`), তাই সেটিংস খালি থাকলেও সাইট ঠিকঠাক চলে।

**SEO।** প্রতিটি পাতায় মেটাডেটা, পণ্যের পাতায় schema.org `Product` (দাম, স্টক,
রেটিং) ও `BreadcrumbList`, হোমপেজে `Store` ও `WebSite` — `src/lib/jsonld.ts` দেখুন।

## ছবি

আপলোড করা ছবি `public/uploads/` এ জমা হয় এবং `/uploads/...` ঠিকানায় দেখা যায়
(JPG, PNG, WEBP, AVIF; সর্বোচ্চ ৫ মেগাবাইট, একসাথে ৮টি)। নমুনা ডেটার ছবিগুলো
`npm run images` দিয়ে তৈরি করা SVG — বাইরের কোনো ছবির উপর নির্ভরতা নেই।

বাইরের কোনো ঠিকানা থেকে ছবি দেখাতে চাইলে `next.config.ts` এর
`images.remotePatterns` এ সেটি যোগ করতে হবে।

## লাইভে নেওয়ার আগে

- [ ] `AUTH_SECRET` — লম্বা এলোমেলো একটি নতুন চাবি বসান
- [ ] `ADMIN_PASSWORD` বদলান, অথবা লগইনের পর অ্যাকাউন্টের পাসওয়ার্ড পাল্টে নিন
- [ ] `NEXT_PUBLIC_SITE_URL` — আসল ডোমেইন বসান (সাইটম্যাপ ও schema.org এর জন্য)
- [ ] অ্যাডমিন সেটিংসে দোকানের ফোন, ঠিকানা, বিকাশ/নগদ নম্বর ও ডেলিভারি চার্জ ঠিক করুন
- [ ] `public/uploads/` ও SQLite ফাইলটি এমন জায়গায় রাখুন যা ডিপ্লয়ে মুছে যায় না;
      নিয়মিত ব্যাকআপ নিন
- [ ] `npm run db:seed` **লাইভে চালাবেন না** — এটি আগের সব ডেটা মুছে ফেলে

> SQLite ফাইল ও আপলোড করা ছবি ডিস্কে থাকে, তাই সার্ভারলেস হোস্টিং (যেমন Vercel)
> এর জন্য আলাদা ব্যবস্থা লাগবে। স্থায়ী ডিস্ক আছে এমন হোস্টে (VPS, Fly, Render)
> সরাসরি চলে।
